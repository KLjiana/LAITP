# K230 板端可行性准备（规划，未实现）

状态：**规划资料**。本文只整理 K230 最小转换/部署实验所需的前置条件、未知项与验证门槛，**不代表已实现或已验证**。当前仓库只实现契约 `1.0` 的图像分类（主机端），检测、量化、板端推理都未开始。

关联：[总体路线与项目大纲](roadmap.md)、[模型接口与产物契约](model-contract.md)、[契约校验说明](contract-validation.md)、[离线分发包](offline-bundle.md)。

## 1. 目标与边界

- 目标：在 K230 开发板上跑通一个**检测**模型的最小闭环（摄像头输入 → 推理 → 屏幕/串口输出），并接入既有任务协议与模型包校验思路。
- 不在本阶段：完整课堂 UI、多模型管理、K210 兼容、检测训练效果的课堂验收。
- 启动条件（缺一不可）：拿到 K230 板卡与配套摄像头/屏幕；确定 CanMV/K230 SDK 与 nncase 的具体版本；确认其工具链可在**离线**环境分发。
- 验收原则：转换成功不等于板端可用；必须有可追溯固定样本的板端输出比对，且量化后精度下降在可接受范围。

## 2. 现状与缺口

| 项目 | 现状 |
| --- | --- |
| 分类契约 1.0 | 已实现：`manifest.json`、ONNX、`labels.json`、固定样本、SHA-256、严格校验，仅 `host` 执行方 |
| 检测数据/标注 | 未实现（无画框、无标注格式、无检测数据清单） |
| 检测训练 | 未实现（无 YOLO 训练链、无检测评估） |
| ONNX 导出/量化 | 分类已导出 ONNX；检测导出与量化未实现 |
| nncase / K230 工具链 | 本机未安装、未固定版本、未验证离线可得性 |
| 板端运行时 | 无 K230/K210 硬件，未验证摄像头、显示、内存与耗时 |
| 任务协议 | 已实现主机端 `1.0`（图像分类）；检测任务类型按契约显式拒绝 |

## 3. 候选技术路线（待验证，不作承诺）

```text
检测数据（类别/图片/框标注）
  → YOLOv8n（或经资源评估更小的检测网络）训练
  → 导出 ONNX（固定输入尺寸、opset 与预处理一致）
  → nncase 量化转换（uint8/int8，校准集来自训练/验证数据）
  → K230 kmodel 部署
  → 板端摄像头采集 → 推理 → 后处理（NMS）→ 结果输出
```

关键未知项：

1. **芯片与 SDK**：K230 具体型号、CanMV 固件版本、nncase 版本三者兼容矩阵。
2. **算子与输入约束**：YOLOv8 结构在 nncase 的目标算子集与分辨率/通道限制；是否需要裁剪或替换算子。
3. **量化精度**：int8 量化对检测框与类别的影响，需固定校准集与量化前后比对阈值。
4. **资源**：模型大小、内存占用、单帧耗时、摄像头分辨率与帧率。
5. **后处理位置**：NMS 放在板端（C/Python）还是主机；结果如何映射到契约字段。
6. **离线分发**：转换工具链、固件、驱动、示例工程能否随离线包分发，许可是否允许。
7. **契约扩展**：检测需要新的任务类型与产物字段（如框坐标、得分、类别顺序），这属于契约兼容性变更，需按契约规则升级版本并同步 Schema、生产方、消费方与验证。

## 4. 建议的验证门槛（未来执行时使用）

按顺序、每步留证，任一步失败则停止并记录原因：

1. **工具链离线可用**：在断网机器上安装并运行 nncase 转换示例；版本固定并记录。
2. **ONNX 一致性**：固定输入样本在 PC 端 ONNX Runtime 与转换前模型输出一致（数值级）。
3. **量化精度**：固定验证集上量化前后 mAP/类别一致率下降不超过预设阈值（阈值待课堂需求确定）。
4. **板端推理**：同一固定样本在板端输出与 PC 端一致性检查（至少类别/框中心容差）。
5. **实时性**：摄像头输入下达到课堂可接受的帧率与延迟，并记录内存峰值。
6. **契约与打包**：板端产物纳入模型包校验流程；离线 ZIP 内含所需工具与固件。

## 5. 需要外部输入的事项

- K230 开发板、摄像头、屏幕与调试线。
- 厂商 SDK/固件与 nncase 的**指定版本**及离线安装包。
  模板：`configs/k230-toolchain.example.json`（复制为 `configs/k230-toolchain.json` 并填入**实际验证过**的版本；空值或缺失时启动条件自检保持 blocked，不要凭推测填写）。
- 板端资源限制（内存、算力、支持算子）的官方文档或实测结论。
- 检测训练所需的课堂/公开标注数据与标注规范。
- 是否允许在离线分发包中再分发固件与转换工具（许可确认）。

## 6. 本机已完成的可复用基础

- 契约校验器与模型包结构（分类）：可复用于板端产物的字段/摘要校验思路。
- 固定样本比对与 SHA-256 校验流程：可作为板端一致性验证模板。
- 行 JSON 任务协议与超时/取消/迟到消息处理：可作为板端任务适配的参考。
- 离线打包与包内自检机制：可扩展为“板端转换工具 + 固件”的离线分发。
- **ONNX 静态图探测（2026-11-23）**：`scripts/k230_model_probe.py` 可读取模型契约 1.0 的模型包（按 `files[role=model]` 定位 ONNX），输出算子分布、输入输出形状/动态维度、参数量、ONNX opset、manifest SHA-256 是否匹配等 JSON。以本机真实数据训练产物实测：MobileNetV3 结构 **922,683 参数**、输入 `[1,3,224,224]` 静态、算子以 Conv(52)/HardSwish(18)/Relu(14) 等为主、无 `NonMaxSuppression`/`GridSample` 等需人工核对算子、manifest 摘要匹配。该结果**只是转换前置事实**，不代表已通过 nncase 转换或板端运行；仍需按第 4 节门槛在指定工具链上验证。
- **随仓库证据**：上述静态探测与启动条件自检结果已归档到[docs/evidence](evidence/README.md)（`k230-static-probe-real-data.json`、`k230-readiness-real-data.json`），可用脚本重新生成；文件内路径属于本机环境，不构成转换或板端证据。
- **启动条件自检脚本（2026-11-23）**：`scripts/k230_readiness.py` 把启动条件变成可复现清单（工具链版本配置 `configs/k230-toolchain.json`、nncase 是否安装、模型静态输入/算子提示、manifest 摘要、校准数据数量），输出 `blocked` 或 `ready-for-conversion-attempt`。本机真实模型自检结果：**blocked**（缺工具链固定配置、nncase、校准数据），模型侧三项通过（静态输入 `[1,3,224,224]`、922,683 参数、无高危算子提示、manifest 摘要匹配）。

## 7. 结论

K230 最小实验**尚不具备启动条件**（无硬件、无固定工具链版本、无检测链路）。在有板卡与指定工具链后，按第 4 节门槛逐步执行；在此之前不将检测、量化或板端部署标记为已实现，也不对外承诺课堂可用性。
