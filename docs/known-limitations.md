# 已知限制与验收边界

本文集中列出**当前交付物的已知限制**与**证据边界**，供接手人、验收人和课堂使用者快速判断“能承诺什么、不能承诺什么”。详细证据见[项目状态报告](status-report.md)、[验证证据索引](verification-evidence.md)、[目标机离线验收清单](acceptance-checklist.md)。**没有证据的项目一律不写成已通过。**

## 1. 证据边界（最重要）

- 目前所有验证都是**开发机 / 解压环境证据**：包括 16 步一键验证、11 环节包内验收、真实数据演练、界面自动化。
- **尚未执行**：干净 Windows 目标机（非开发机、普通用户权限）、真正断网（拔网线/隔离网络）、真实课堂数据采集、物理摄像头现场验收。
- 因此不得把本仓库任何“通过”表述理解为目标机端到端可用；目标机结论必须由目标机执行[目标机验收操作卡](acceptance-card.md)与[离线验收清单](acceptance-checklist.md)后得出。

## 2. 摄像头

- 摄像头相关自动化验证按用户要求于 2026-11-18 起**停止**，历史结果只作历史证据；相关验收项 A11 保持“部分”。不要恢复 `--camera` 自动化测试或据此宣称通过。
- 设备选择、拍照导入、预览等能力曾实现并做过程序化检查，但目标机摄像头兼容性未验证。

## 3. 离线与分发

- 离线包为**解压即用**，不含安装器、自动更新、远程服务；不保证在未安装 .NET Desktop Runtime 的机器上运行框架依赖版本（包内桌面为自包含发布，自检会校验）。
- 当前环境验证不含“真正断网”，网络隔离后的行为需目标机复验。
- 长路径：本机在 `LongPathsEnabled=1` 下以约 300 字符完整路径解压并自检通过（仅本机证据）；未启用长路径且路径过长时可能失败，建议使用短路径（如 `D:\LAITP`）。
- 杀毒扫描/系统负载会显著影响解压、启动与训练耗时；报告记录耗时仅作参考。

## 4. 性能与耗时

- 所有耗时为本机单次测量，随负载波动（构建 2–15 分钟、验收 3–6 分钟、训练 CPU 时间等均有浮动）。
- 课堂时间预算与目标机性能（CPU、内存、磁盘、启动时间）仍未确认，不能据此承诺课堂节奏。

## 5. 模型契约与检测

- 当前可用契约是**分类 1.0**（manifest/ONNX/labels/固定样本/SHA-256、host 侧预处理）；分类链路已实现并验证。
- **检测（M3+）仍是草案/未激活**：P1/P2 为草案（待评审），Q1–Q8 决策未定，P3–P9 未实施；不要将检测 Schema、草案校验器或探测工具视为可用功能。
- 检测 ONNX 导出探测仅为**可行性证据**（SSDLite/FasterRCNN 随机权重、本机单次）：无图内 NMS、含控制流算子、未训练、未转换、未量化、未板端验证。
- K230/K210 的 nncase/工具链、板端推理、内存与帧率均未验证。

## 6. 数据

- 没有真实课堂/学生数据；真实数据验证使用的是公开数据集与固定样本，不代表课堂分布。
- 课堂数据采集、标注与隐私合规需在真实部署阶段另行处理。

## 7. 验收工具本身的限制

- 包内验收对界面步骤提供：残留进程预检清理、有界超时（180–600 s）、失败**透明单次重跑**（首次失败写入 `warnings`，不掩盖）。单次重跑不能消除 UI 自动化偶发抖动。
- `check_state` 只做轻量 ZIP 结构检查（manifest 引用/桌面自包含/启动脚本），**不替代**包内完整自检（逐文件摘要校验）与人工界面核对；包内自检本身已做逐文件摘要校验，并校验 manifest 环境声明与包内实际一致、扫描第一方文本开发机绝对路径，但仍不能替代人工界面核对与目标机验收。
- 报告中的“包身份”（manifest 摘要）用于把验收记录对应到具体分发包，不构成发布签名。

## 8. 其它

- 本仓库从未在真实学校网络/机房环境部署；离线包只做过解压运行验证。
- 当前 git 提交包含源代码与文档；`dist/`、`artifacts/`、`.venv/`、`.dotnet/`、`vendor/` 等生成物不入库，交接时需从构建机取得 `dist/handoff/`。
