## 1. 项目目标

用学生采集的小规模图片，在 CPU 上训练分类模型，生成完整模型产物包。关闭训练程序后，由独立进程仅凭模型包及待测图片完成校验、加载和预测，全过程可断网运行。

本任务回答三个问题：

1. 普通电脑能否以可接受的资源消耗训练分类器？
2. 输入输出、类别顺序及预处理等信息能否完整传到推理端？
3. 模型复制、重新加载和环境变化后，结果是否仍满足约定？

成功后产出的后端能力供 WPF 接入，不把一次命令行演示视为完整教学软件。

- 模型交接验证、关键失败场景验证及离线运行记录。

## 3. 技术基线与前置条件

| 项目 | 初始方案 | 决策要求 |
| --- | --- | --- |
| 训练方式 | 冻结轻量预训练特征提取器，只训练线性分类头 | 记录特征提取和分类头训练各自的耗时；不采用从零训练深层网络 |
| 候选网络 | 优先评估 MobileNetV3-Small | 确认权重来源、许可证、CPU 性能及导出兼容性后固定版本 |
| 训练框架 | 优先评估 PyTorch 与对应模型库 | 固定 Python、框架及模型库的兼容版本，使用 CPU 路径 |
| 部署格式 | 优先采用 ONNX，使用 ONNX Runtime CPU 推理 | 固定支持的 opset 和运行时版本；导出特征提取器及分类头组成的完整网络 |
| 数据处理 | 共用明确的图像解码及预处理定义 | 参数来自契约，不在训练和推理命令中分别硬编码 |
| 开发环境 | Linux 可开发后端；Windows x64 验证目标运行能力 | 两种平台分别记录依赖和结果，不互相替代验收 |
| 本地资源 | 预训练权重、模型包和依赖在离线验证前备齐 | 使用明确的本地路径；缺失时立即报错，不自动下载 |

以上为实施起点，不是已验证的选型。需要调整时记录原因、替代方案和受影响的验证，保持契约语义一致。

开始性能验收前确定目标 Windows 电脑的 CPU、内存、系统版本和课堂训练时间预算。信息未齐时可以完成 Schema、校验器和 Linux 功能验证，但课堂性能及 Windows 验收状态保持待验证。

## 4. 数据准备

选择三类容易区分且便于重复采集的物品，例如水杯、书本和笔袋。初始数据规模建议为：

- 每类 30～50 张开发图片，至少来自多个独立采集批次，用于训练和验证。
- 每类另采至少 10 张测试图片，换背景、距离或角度，不参与调参。
- 按采集批次划分训练与验证集，初始比例约为 80% / 20%；以每类均有独立批次为优先，不强求精确比例。

数据清单记录样本相对路径、内容摘要、类别 ID、采集批次及所属划分；类别 ID 使用显式有序表确定，不依赖目录遍历顺序。

检查空类别、无法解码的图片、重复文件和跨集合重复。保留不可变快照或可恢复的数据版本。测试集冻结后，若根据其结果修改方案，应另设新的最终测试集。

固定交接样本用于验证模型传输与推理一致性；独立测试集用于评估识别效果，二者不得混为一个指标。

真实图片暂未提供时，可用小型构造样例推进校验器测试，但不能据此声称真实分类效果或课堂可行性已通过。

## 7. 命令行与进程接口

以下操作已实现，具体调用语法见各阶段实施记录与相关说明：

| 操作 | 输入 | 输出 |
| --- | --- | --- |
| `train` | 数据清单、本地预训练权重、训练配置、输出目录 | 训练产物包、训练记录及指标 |
| `export` | 训练产物包、导出配置、输出目录 | 带来源关系的 ONNX 产物包和转换验证记录 |
| `validate` | 模型包、目标运行时及验证配置 | 结构、完整性、语义和固定样本检查结果 |
| `predict` | 模型包、图片 | 类别 ID、类别名称、各类概率及产物 ID |
| `evaluate` | 模型包、冻结的评估数据清单 | 准确率、各类召回率、混淆矩阵及误判清单 |

标准输出仅传按行 JSON 消息，标准错误输出日志，失败返回非零退出码。消息使用模型契约规定的身份字段和序号。

使用最小父进程测试程序验证启动、进度、结果归属和取消，不依赖 WPF。取消后清理或保留可识别的临时文件，不发布未完成模型；迟到成功消息不能改变已取消任务的状态。C#/WPF 集成已在 M1 完成（见[桌面外壳](desktop-shell.md)），目标机进程集成验收仍待执行。

## 8. 验收矩阵

| 验收项 | 检查方法 | 通过条件 |
| --- | --- | --- |
| CPU 训练 | 使用冻结数据和本地权重执行训练 | 未使用 GPU，产生有效训练记录与模型包 |
| 独立加载 | 退出训练程序，将 ONNX 包复制到新位置，用新进程预测 | 不访问训练目录，标签和处理参数从包读取，正确输出预测 |
| 输入一致性 | 固定样本分别走训练端与部署端预处理 | 张量形状、布局、颜色和数值符合预定比较规则 |
| 导出一致性 | 比较训练框架与 ONNX Runtime 的原始输出及预测 | 输出误差和预测一致性达到预先冻结的阈值 |
| 真实效果 | 使用独立测试集评估 | 报告总体及各类指标，满足预先确定的效果目标 |
| 错误标签 | 修改标签顺序但保留原摘要；另构造类别数不匹配的包 | 分别因完整性和语义错误拒绝，不能静默运行 |
| 损坏或不完整产物 | 修改权重、移除文件、提供临时包 | 明确拒绝，不产生成功结果 |
| 版本及路径 | 提供不支持版本、未知必需操作和越界路径 | 拒绝并指出具体原因 |
| 取消与异常 | 中途取消、使子进程异常退出并模拟迟到消息 | 无错误发布、无错误模型切换，任务有明确终态 |
| 路径可移植性 | 使用中文和含空格路径，复制包后运行 | 无开发机绝对路径依赖 |
| 离线 | 备齐资源、移除对下载缓存的隐式依赖并断网运行 | 训练、导出、加载与预测均完成，无运行时下载要求 |
| Windows 目标机 | 在目标 Windows x64 CPU 环境重复链路 | 保存实际日志和性能数据；Linux 结果不能代替此项 |

SHA-256 只能检测相对于清单的修改，不能证明标签本身语义正确。生成阶段必须核对训练类别映射，固定样本和来源记录共同用于检查语义一致性。

## 9. 性能和数值阈值

首次探索性运行用于选型和建立基线。正式验收前，将数据摘要、类别数、输入尺寸、随机种子、线程数、依赖版本、硬件及阈值保存为版本化配置。

至少记录：

- 特征提取、分类头训练及完整训练的耗时。
- 导出耗时、模型包大小和峰值内存。
- 新进程加载耗时，以及预热后单图预测延迟的中位数和 P95。
- 原始输出的绝对/相对误差、预测一致性及实际测试集效果。
- 完整测量范围、预热次数、测量次数和失败次数，避免混淆冷启动与稳态性能。

训练时间预算、内存上限、推理延迟目标、效果目标和数值容差在 T03 建立正式验收配置，受后续导出能力影响的项目须在正式验收前补齐。未设定阈值时只能报告测量结果，不能判定课堂性能达标；不得看到失败结果后临时放宽阈值。

## 12. 风险与处理

| 风险 | 处理方式 |
| --- | --- |
| CPU 训练过慢 | 分开测量特征提取与训练，评估缓存特征、限制线程及更轻网络；缓存键包含权重、数据和预处理摘要 |
| 样本相似导致虚高效果 | 按采集批次划分，保留不同场景的独立测试集，报告各类结果 |
| 导出不兼容或数值不一致 | 固定模型与工具版本，逐段检查预处理、网络输出及后处理，不跳过对比 |
| 权重或依赖依赖联网 | 在正式断网测试前准备明确的本地资源清单，缺失时给出错误 |
| Windows 原生依赖差异 | 提前进行 Windows 小规模试运行，再完成目标机验收 |
| 暂无真实数据或 Windows 机器 | 推进可独立完成的实现和 Linux 验证，将对应验收标记为未执行，保留具体阻塞 |
