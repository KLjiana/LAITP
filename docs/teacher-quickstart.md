# 老师快速上手（离线桌面版）

本文面向第一次使用的老师，按顺序操作即可完成“建项目 → 采集图片 → 检查 → 训练 → 预测”。全程离线，不需要安装 Python 或 .NET，也不用联网。

## 1. 准备与启动

1. 把离线包解压到本机磁盘（例如 `D:\LAITP`）。不要放在只读目录、U 盘或网络共享盘上。
2. 双击 `start-desktop.bat` 启动。首次启动会自动自检，状态栏显示 **“就绪（环境自检通过）”** 即可使用。
3. 若状态提示找不到 Python 或仓库目录，请确认是从解压目录内的 `start-desktop.bat` 启动，且 `python\python.exe`、`desktop\app\` 均存在。

想先确认文件完整，可双击 `check-bundle.bat`：它会校验全部文件并试跑推理/报告/桌面，最后显示 `"ok": true`。

## 2. 新建项目

1. 在“项目”区填写：
   - **项目根目录**：项目保存位置（建议英文或中文均可，避免特殊符号）。
   - **项目名称**：如“三年级垃圾分类”。
   - **类别**：至少 2 类，用空格分隔，如 `可回收物 厨余垃圾 其他垃圾`。
2. 点击 **新建项目**，项目路径会显示在“当前项目”。
3. 再次上课时，可从 **最近项目** 下拉框选择并点 **打开最近**；需要复制一份项目时，填写“另存为目录”后点 **另存为**（目标目录必须不存在或为空）。

每类建议至少 30 张训练图片；越贴近课堂真实场景，效果越好。

## 3. 采集与导入图片

界面提供三种方式，可混用：

- **摄像头拍照**：选择“导入类别”，在摄像头行点 **检测/刷新** 确认设备，再点 **拍照**（每张自动导入当前类别并形成批次）；也可设置张数后点 **连拍**。注：真实物理摄像头未验证；摄像头自动化测试已于 2026-11-18 按要求停止，界面采集以 DroidCam 历史记录为准。
- **导入来源文件夹**：来源目录按 `来源/类别/批次/*.png` 组织，点 **批量导入**。
- **导入图片**：选择图片文件，逐个加入当前类别。

勾选 **导入为测试集** 时，图片进入测试集而不是训练集。

拍照/导入后，右侧会显示数据清单（各类别训练/验证/测试数量）。若提示重复内容，说明同一张图片被重复采集，请换角度或删除重复样本。

## 4. 检查数据

点击 **检查数据**：

- 显示“数据检查通过，可以开始训练”即可继续。
- 显示未通过时，按提示处理（常见：某类样本太少、训练/验证划分不足、重复图片）。
- 勾选 **严格验收** 可执行目标机验收策略；样本不足时失败属于预期，用于验收而非日常使用。
- 课前建议点 **数据体检**：生成项目 `runs/dataset-report.md`（每类每批次样本数、重复/无效图片、尺寸分布与风险提示）和 `runs/dataset-samples.csv`（逐样本明细）；成功后状态显示“数据体检完成：N 张样本，X 组重复，Y 张无效，Z 条风险”。体检只读现有数据，不重建清单、不改项目，需要先打开项目。
- 也可用命令行生成同样的体检报告：`python\python.exe scripts\dataset_report.py --project <项目目录> --output report.md --csv samples.csv`。

## 5. 训练与发布

1. 在“训练”区设置训练轮数（默认即可，课堂电脑建议 20 轮左右）。
2. 点击 **训练并发布**。完成后状态显示“训练与导出完成，当前模型：art-run-…”。
3. 训练历史列表可选中记录并 **导出报告**，便于留档或提交。

训练使用本机 CPU，时间取决于图片数量与轮数；期间可点 **取消**。

## 6. 预测与批量测试

**单张预测**：

1. 模型包路径通常已自动填入刚发布的产物；也可手动选择 `exports/art-run-…/model-package`。
2. 选择一张图片，点 **预测**。
3. 状态显示“成功”，并给出类别与置信度。

**批量预测（用于“使用新样本测试、分析误判”）**：

1. 准备测试图片目录，按 `类别/批次/*.png` 组织（例如 `测试/可回收物/batch-1/*.png`）。
2. 在“待测图片”行填写该目录，点 **批量预测**。
3. 状态显示“批量预测完成：N 张，准确率 X%（M 张有真实类别）”，下方消息区显示各类准确率、各批次准确率与误判样本。
4. 逐张结果自动保存到项目的 `runs/batch-predict-<时间>.csv` 与 `runs/batch-predict-<时间>.json`（打开项目时才会写入项目；未打开项目时使用临时文件并在结束后清理），CSV 可用 Excel 打开分析。

如果没有按类别组织图片，仍会逐张预测，但不计算准确率。

**批量预测历史（回看某次结果）**：

训练历史列表下方是“批量预测历史（最近 10 次）”，每次批量预测完成后自动刷新：

1. 列表中每条显示“时间 · 张数 · 准确率”，只保留项目 `runs/` 下最近 10 次 `batch-predict-*.json`。
2. 选中一条后点 **查看选中历史**，下方消息区会追加该次的总体准确率、各类准确率、各批次准确率、错误数量与结果 CSV 路径。
3. 结果文件已被移走或损坏时，状态只会提示“历史结果文件不存在”或“读取历史结果失败”，不影响其它记录，可重新跑一次批量预测。

需要按类别/批次对比时，可在命令行加 `--details-csv` 生成“最近一次运行”的明细表：`python\python.exe scripts\batch_history_export.py --project <项目目录> --details-csv runs\batch-history-details.csv`（表头：类型、名称、总数、正确数、准确率，UTF-8 BOM，Excel 可直接打开）。说明：这是命令行方式，界面“导出历史汇总”按钮暂未导出明细。

**模型对比（比较新旧模型）**：

沿用“待测图片”目录，把当前模型包和另一个模型包放在同一批图上对比：

1. 确认“模型包目录”（模型 A）和“待测图片”已填好。
2. 在“模型对比”下拉框选择项目 `exports/art-…/model-package` 下的历史模型包，选择后会自动填入右侧路径框；也可以直接在路径框手输模型包目录（模型 B）。
3. 点 **模型对比**，状态显示“模型对比完成：A xx% / B xx%，一致率 xx%（N 张）”；下方消息区列出 A/B 两包的产物 ID、准确率、分歧样本（最多 5 条）与提示。
4. 若两个模型包的类别标签不一致，消息区提示“警告：两个模型包标签不一致，准确率/一致率不可比”，此时先确认两次训练用的是同一套类别，不要直接比较准确率。
5. 待测图片没有按类别组织时，准确率显示“无真实标签”，一致率显示“无可用图片”。

对比结果会显示在下方消息区；打开项目时，结果 JSON 同时保存到项目 `runs/compare-<时间>.json`（消息区末尾显示“结果 JSON：<路径>”），可用于课后复查。

## 7. 项目保存与再次打开

- 项目就是项目根目录下的 `project.json`、`data/`、`exports/`、`runs/`。关闭软件不会丢失。
- 再次使用：从 **最近项目** 选择后点 **打开最近**，或填写 `project.json` 路径后点 **打开项目**，清单、历史会自动恢复。
- 备份：直接复制整个项目目录即可；也可以使用 **另存为** 生成副本。不要只拷贝 `project.json`。
- 项目归档：在项目区“项目归档（单文件 ZIP）”填一个 `.zip` 路径（例如 `D:\备份\三年级垃圾分类.zip`），点 **导出存档** 生成单文件 ZIP；到另一台电脑填同一个 ZIP 路径后点 **从存档导入**，归档会解压到 ZIP 同名文件夹并自动打开项目。**导入目标文件夹必须不存在**：若已存在同名文件夹，界面提示“导入目标目录已存在”，请换一个归档目录或先把已有文件夹移走。
- 也可用命令行归档：`python\python.exe scripts\project_archive.py export --project <项目目录> --output <归档.zip>`，迁移时用 `import` 恢复。

## 8. 常见问题

| 现象 | 处理 |
| --- | --- |
| 状态“未找到 Python 解释器” | 从解压目录的 `start-desktop.bat` 启动；确认 `python\python.exe` 存在 |
| 双击 exe 提示必须安装 .NET Desktop Runtime | 不要运行 `desktop\src\...\bin` 下的开发构建 exe；请用解压目录的 `start-desktop.bat` |
| 状态“未找到可用摄像头” | 检查设备连接；在 Windows 设置 → 隐私 → 相机 允许应用访问；设备管理器中确认未被禁用 |
| “摄像头被其他程序占用” | 关闭视频会议/相机等占用程序后重试 |
| “摄像头权限被拒绝” | 在 Windows 设置 → 隐私 → 相机 中允许桌面应用访问 |
| 数据检查未通过 | 按提示补样本、去重或调整训练/验证划分 |
| 训练失败 | 查看界面“产物/报告”区域与 `runs/` 下的日志；确认磁盘空间充足 |
| 批量预测准确率为空 | 测试目录需按 `类别/批次/*.png` 组织，才能按目录名统计准确率 |
| 批量预测历史为空或“查看选中历史”不可点 | 先打开项目并至少完成一次批量预测；列表只显示项目 `runs/` 下最近 10 次 `batch-predict-*.json` |
| “查看选中历史”提示“历史结果文件不存在” | 该次结果文件已被移走或删除，重新跑一次批量预测即可 |
| 模型对比提示“标签不一致，不可比” | 两个模型包训练时类别不同；换成同一套类别训练的模型包再对比 |
| 从存档导入提示“导入目标目录已存在” | 归档会解压到 ZIP 同名文件夹；换一个归档目录，或先移走同名文件夹 |
| 数据体检提示“请先打开项目文件” | 先新建或打开项目，再点 **数据体检** |
| 双击 `check-bundle.bat` 报文件摘要不符 | 重新解压离线包（不要改动包内文件）；仍失败则重新获取分发包 |

## 9. 课堂建议

- 课前先跑一次 `check-bundle.bat` 和“检查数据”，避免课上排障。
- 每类样本尽量在同一光照、同一背景下采集，数量均衡。
- 拍照后留意“重复内容”提示，避免同一画面反复采集。
- 讲评环节用 **批量预测** 跑一遍新测试图，结合误判列表、CSV 和“批量预测历史”回看，讨论“为什么认错、要补什么数据”。
- 讲评可按“**批量预测** → 看各类/各批次准确率 → **模型对比**（比较新旧模型）→ 看 **数据体检** 报告”的顺序展开：先用准确率定位薄弱类别，再用模型对比说明新模型是否真的更好，最后用体检报告指出下一轮要补哪类、哪批样本。
- 每完成一个班/一个主题，复制一份项目目录作为备份。

## 10. 环境预检与问题取证（交给管理员/验收人）

- 验收或排查前可先做只读环境预检：`python\python.exe scripts\preflight_target.py --root .`（检查平台/权限/路径长度/磁盘/内存/包文件/摘要/长路径/代码页；只做静态检查，不代表验收通过）。
- 验收后可用 `python\python.exe scripts\collect_evidence.py` 打包验收产物与报告，生成带 `evidence-manifest.json`（逐文件 SHA-256 与缺失项）的 ZIP，与现场记录一起回传。
- 完整验收步骤与记录模板见 `acceptance-card.md` 与 `acceptance-checklist.md`。
